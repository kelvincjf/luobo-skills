# 萝卜·逻辑写作

先让人读懂整件事，再考虑分几页、画什么图。此技能是写作与配图的共同子步骤，不替代来源核验、作者风格、图片渲染和平台发布，也不自行发布内容。

## 先确定任务范围

复用本轮素材和已确认要求，明确读者、读者的问题、看完应理解或能做什么。缺失且会改变写法的信息才问。只改格式、短句或只标问题时按原范围直接处理；本人定稿不因“结构优化”被擅自重写。

## 写作顺序

1. **写出中心意思。** 用一句普通话回答读者的问题，保留决定性条件和未知。只有“几大特点”“全面赋能”不算答案。可用切题的经历或问题开场，但不能迟迟不交代在讲什么；不强迫故事、悬念和口述稿都第一句抛结论。
2. **选一条主线，并说明为什么。** 流程用时间/依赖；系统用组成与交接；比较用共同标准；建议用结论、理由和证据；故障解释用现象、证据、可能原因与处理。后两类是本技能的应用组织法，不宣称均为Minto原书分类。每组只按一个维度分类；跨组可换顺序，但用过渡句说明。不要每次强套事前、事中、事后或硬凑三点。
3. **先梳理，再拆段/拆页。** 先用一小段连贯话讲清整件事，再列标题链。上级判断要能由下级内容支持；同层内容回答同一类问题，不能把目的、工具、动作和效果混列。流程写谁拿什么做什么、产出是什么、下一步为何需要它，并保留必要失败/停止分支。工具名在承担具体任务时出现。
4. **用MECE查分类。** 先限定本稿讨论范围和分类标准，再查同层重复归属、关键遗漏。重复项合并或明确交叉关系；缺证据留未知，不为“穷尽”编事实、加无关页。步骤可反复调用同一工具，回路不是自动违反MECE；同页可以承上启下。分类整齐不证明事实正确、因果成立或读者看懂。
5. **写正文与分镜。** 一段/一页解释一个主要问题，给具体动作、例子或依据，必要术语首次解释。系统图的箭头说明是先后、信息传递、依赖还是反馈；没有证据的因果不能靠箭头暗示。图片版与文字版的分工按平台和用户要求，见[小红书图文](references/xiaohongshu.md)。
6. **先检查是否讲得通，再做版面检查。** 完成下方阅读检查，发现断层先修对应内容，再渲染；渲染成功、无溢出和字号合格只证明版面。修一页后复看相邻页交接和中心意思，不需要重写全部。用户已定稿且只要求上传时保护定稿，具体实质问题据当前授权处理，不增加每篇审批。

## 阅读检查（代理执行，不强迫用户做作业）

- **标题连读：** 隐去正文，按标题顺序能否知道讲什么、怎么展开、落到哪里？名词堆叠或换序仍无区别的流程标题，需重组。并列比较可换序，不机械套此诊断。
- **连接检查：** 任意相邻两段/页，能用正常一句话解释为什么接着讲它吗？流程中“下一步”的输入有没有出现？
- **陌生读者复述：** 不借助作者私有背景，按当前成稿复述核心意思；流程再说出第一步、下一步和结束条件。说不出时补主语、解释或例子，不只加图标。模型自检只叫自检；无人参与不能记为真实读者通过。
- **关键内容对照：** 用户要求/已核事实→对应段落或页，核漏项、重复、层级和限定。有明确问题则记录具体位置、修法及复查结果，不能只打“符合MECE”的勾。

起稿可在已有Brief中留“读者问题｜中心意思｜主线与理由｜标题链｜覆盖与缺项｜检查结果”六项，不另建繁重表单。简单编辑不强制记录。参考[具体例子](references/examples.md)与[来源及取舍](references/sources.md)；按需读，不每次联网重研。

## 边界

结构不能制造证据，流畅不能掩盖未知，不用绝对化语气替代论证。不规定页数、emoji、段落数量或结论必在首句；保留作者真实语气。现有研究、短答、微调、只评不改和发布权限继续有效。没有对照测量，不宣称提升理解率、速度或节约Token。
