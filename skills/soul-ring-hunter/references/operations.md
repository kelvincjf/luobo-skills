# 单目录操作与恢复

仅限已获准的普通技能目录。Python 3 标准库，无模型、网络、管理员权限或自动授权功能。

1. `python3 <skill>/scripts/skill_ops.py prepare --candidate <候选目录> --target <目标目录> --run <不存在的事务目录>`
2. 读取并执行 `<事务目录>/candidate/SKILL.md`。输入、产物、检查结果保存到该事务目录。新例必须为真实候选执行；更新已有技能还要旧例。
3. 编写 `<事务目录>/validation.json`，结构如下；所有路径相对此事务目录，哈希按实际文件计算。

```json
{
  "candidate_sha256": "从 transaction.json 取得的冻结候选指纹",
  "new_case": {
    "status": "passed",
    "kind": "behavior",
    "invocation": "实际如何读取或加载候选并执行",
    "runtime": "实际宿主、模型或 unknown、依赖版本",
    "evidence": [{"path": "checks/new-case.json", "sha256": "文件的真实SHA256"}]
  },
  "old_case": {
    "status": "passed",
    "kind": "behavior",
    "invocation": "实际旧任务执行方式；更新时必填",
    "runtime": "实际环境",
    "evidence": [{"path": "checks/old-case.json", "sha256": "文件的真实SHA256"}]
  }
}
```

4. 代理核对语义结果和当前授权，再运行 `apply --run <事务目录>`。它验证文件存在、哈希与必要记录，无法判断“passed”是否诚实，也不防御能同时篡改全部本地证据的操作者。
5. `status --run <事务目录>` 只读比较；`rollback --run <事务目录>` 恢复本次目标，后续用户改过目标则拒绝覆盖。

候选变更后另开新事务，重新验证，保留旧失败记录。应用同一事务两次不会重复写入。不同事务会在同一目标目录旁使用短暂互斥锁；只有能确认原进程不存在才清理死锁，不凭超时强拆。

已有目标的替换分两步：原目录移到 `previous/`，冻结候选的副本移到目标。**这是有日志、可恢复的替换，不是两步合为一个原子操作**；中间短暂没有目标，不适合有程序不断读取的生产服务。脚本在首次移动前写 `applying`。中断时先 `status`，原目录和候选均保留，按现场运行 `rollback`；不盲目再次 `apply`。成功恢复后核对原指纹。操作期间避免其他工具同时写目标；锁只协调本工具，不能锁住编辑器。

事务、候选、目标不得互相嵌套，事务与目标须同一文件系统。含 `.git` 的目录不支持整体替换，使用仓库内独立技能子目录；不能在替换中丢掉版本库元数据。验证证据必须是事务目录内的普通文件，不能用软链接替代。多目录和多镜像分开记录及恢复，不声称跨目录原子性。不修改系统同步数据库、不操作全仓 Git、不扫描隐式个人目录。
