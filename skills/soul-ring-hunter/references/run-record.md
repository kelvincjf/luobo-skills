# 一次吸收的最小记录

只填写实际经过的阶段，简单复用不强行制作全部附件。记录放在本地私有运行目录；公开演示另用合成材料。

```markdown
# <运行编号>｜<能力目标>
## 输入与授权
- 本轮要解决的具体任务、输入、最终产物和成功标准：
- 可扫描技能目录、可读背景、可改目标、当前/目标环境：
- 来源定位、读取时间、版本/指纹、完整性、必要引用：
## 盘点与用途
- 已有相关入口及证据；镜像/同名异版；未检查范围：
- 当前要求 / 获准背景 → 改变的功能、输出或验收：
- 决定性缺项和真实问答；足够时停止提问的依据：
- 决定：复用 / 参考 / 改造 / 新建 / 暂缓 / 拒绝；理由：
## 方法小试验（改造/新建时）
- 冻结输入、旧做法、预定标准、实际输出与检查：
- 结果及局限：
## 改造计划与候选
- 采用与舍弃，目标文件，保留能力，实际差异：
- 基线/候选指纹、事务目录、恢复方式：
## 候选验收与应用
- 实际加载方式、环境、输入、产物、新例/旧例结果：
- 每次失败与修正、未测项；最终验证对应哪个候选：
- applied / failed / blocked / not_run / reverted：
## 后续
- 原预期、使用记录入口及覆盖、到期时间：
- 调度：下次调用检查 / 已安排（ID）/ 实际执行（证据）：
- 上游（适用时）：仓库、分支、相关路径、吸收依据 commit、目标映射、直接使用/本地改造/仅参考：
- 上次已检查 commit / 已采用 commit / 已评估但不采用的版本与原因（分别记录）：
- 上游变化与本地增量对照、保留的定制、试验/事务证据、下次检查日期：
```

反复改动时保留旧记录，不覆盖首次失败。相同来源 URL 不能作为唯一去重键，还要比较目标、相关背景和运行环境。
